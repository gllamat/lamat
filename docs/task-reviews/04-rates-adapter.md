# Task 4: synthetic rates adapter — review record

**Status:** Ready for review; [pull request #21](https://github.com/gllamat/lamat/pull/21) has not been merged.

**Board task:** [Implement a provenance-aware rates data adapter](https://github.com/gllamat/lamat/issues/4).

## What to review

The example now reads a small local 2-year, 5-year and 10-year rates fixture instead of using hard-coded rates. A replaceable provider interface returns observations together with provenance. The fixture is manually specified synthetic data, not historical or current market prices.

- [Rates provider](../../packages/quant-research/src/lamat_quant/rates.py): source, licence, units, revision and missing-data policies; dates and rate validation.
- [Synthetic fixture](../../data/fixtures/synthetic-rates.json): three dated observations in percent per annum.
- [Example](../../examples/mean_reversion.py) and [methodology](../mean-reversion.md): display the source and use the latest fixture row for the butterfly.
- [Tests](../../packages/quant-research/tests/test_rates.py): verify provenance, an independently calculated butterfly and rejection of missing fields, non-finite rates, duplicate dates and unsupported units.

## Reproduce the checks

From the repository root, with Python 3.9 or later:

```sh
PYTHONPATH=packages/quant-research/src python3 -m unittest discover -s packages/quant-research/tests
PYTHONPATH=packages/quant-research/src python3 examples/mean_reversion.py
```

The local run passed all five tests. The example reported synthetic source and `percent per annum`; for 19 January 2024 the illustrative butterfly was approximately **0.1 percentage points** (`-4.0 + 2 × 3.85 - 3.6`). The separate OU series is generated by a seeded simulation; it is not calibrated to these three fixture rows.

## Boundaries and remaining work

The adapter rejects missing values within an observation but does not detect missing calendar dates, fill gaps, fetch a live data source, track actual revisions or perform point-in-time selection. Those capabilities and real-data licensing must be designed before using market data. Data values and the reported butterfly do not imply a trading result.

**Human review:** check that the provider contract, provenance fields and reject policy meet the intended use. Review the pull request and its automated checks before approving a merge. The board card should move to Done only after the reviewed change is integrated.
